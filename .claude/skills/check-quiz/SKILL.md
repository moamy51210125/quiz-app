# check-quiz：クイズアプリの確認・修正ループ

対象：`quiz-app/<フォルダ名>/` にある `index.html`・`style.css`・`script.js` の3ファイル構成のクイズアプリ。
引数でフォルダ名が渡されなければ、直前に作成・変更したアプリを対象にする（わからなければユーザーに聞く）。

このスキルのフォルダを `SKILL_DIR`、アプリのフォルダを `APP_DIR` とする。

## 手順

### 1. 自動チェック（構文・問題データ・書き方のルール）

```bash
node "$SKILL_DIR/validateQuiz.mjs" "$APP_DIR"
```

確認すること：JavaScript の構文エラーがない／問題が30問ある／全問が4択で選択肢の重複がない／正解番号が正しい範囲にある／問題文の重複がない／`var`・`innerHTML`・`getElementById` を使っていない。

### 2. ブラウザ操作テスト

```bash
node "$SKILL_DIR/browserCheck.mjs" "$APP_DIR/index.html" "<スクリーンショット保存先フォルダ>"
```

- 保存先はスクラッチパッド（なければ OS の一時フォルダ）にする。アプリのフォルダには保存しない
- ヘッドレスの Chrome（なければ Edge）をスマホ幅（375px）で開き、次を自動で操作・確認する：
  - 開始時にランダムに10問が選ばれる
  - 交互に正解・不正解で10問回答し、フィードバック・色分け・「次の問題へ」／「結果を見る」が正しく出る
  - 結果画面に「10問中5問正解」が出る
  - 「間違えた問題を解く」で間違えた5問だけ出題され、全問正解するとボタンが隠れる
  - 「もう一度最初から」で別の10問が選ばれる
  - 正解の位置が1〜4番目にばらつく（選択肢シャッフル）
  - 横にはみ出さない
  - コンソールにエラー・警告がない
- スクリプトは、アプリが共通の作り（下記「前提」）になっていることを前提にしている。作りが違うアプリでは、スクリプトをそのアプリに合わせて直してから使う

### 3. 見た目の確認

保存されたスクリーンショット（`1-feedback-wrong.png`・`2-result.png`・`3-question.png`）を Read で実際に見て、次を確認する：

- 文字が小さすぎたり、薄すぎて読みにくくなったりしていない（回答後の選択肢の文字色も含む）
- 文字やボタンがはみ出したり、重なったりしていない
- 正解は緑・不正解は赤など、区別がつく

### 4. 内容の確認（自動テストではわからない部分）

`script.js` の問題データをすべて読み、次を確認する：

- 問題文・正解・解説の事実が正しい。少しでも不確かなものは「要確認」として挙げる
- 正解がひとつに決まる（別の選択肢も正解と言えてしまわない）
- 対象の学年・テーマに合っている（例：小学3年生向けなら、小3で習う範囲か）
- 解説と正解が食い違っていない

### 5. 修正と再確認（上限3回）

- 1〜4で問題が見つかったら修正し、**1から全部やり直す**
- このくり返しは**最大3回まで**。3回直しても残る問題があれば、それ以上は直さずに止めて報告する
- **自動で直してよいもの**：明らかなバグ、コンソールエラー、CLAUDE.md のルール違反（書き方・仕様）、読みにくい文字色など見た目の小さな不具合
- **直さずにユーザーに聞くもの**：問題の追加・差し替え・削除、事実が不確かな内容の扱い、デザインの大きな変更、ユーザーから「変更しないで」と言われている部分

### 6. 報告

最後に必ず日本語で次を報告する：

- 確認した項目と結果（OK／NG の一覧）
- 修正した内容（ファイル名と、何をどう直したか）
- 残っている問題、ユーザーに判断してほしいこと
- 確認できなかった項目があれば、その理由

## 前提（アプリの共通の作り）

browserCheck.mjs は、次の作りを前提にしている。新しいアプリもこの作りにそろえる。

- 要素の id：`#quiz-screen`・`#result-screen`・`#progress`・`#question`・`#choices`・`#feedback`・`#next-button`・`#score`・`#result-message`・`#restart-button`・`#retry-wrong-button`
- 選択肢ボタンは `.choice-button` で、`data-choice-index` に元の選択肢番号を持つ
- 回答後、正解のボタンに `.correct`、選んだ不正解のボタンに `.wrong` を付ける
- グローバル変数 `questions`（全問題）・`activeQuestions`（出題中の問題）・`currentIndex`（何問目か）がある
- 各問題は `{ question, choices, answer, explanation }` の形
- 進み具合の表示は「第N問 / 全M問」、スコアの表示は「M問中N問正解」
- 正解時のフィードバックに「正解！」、不正解時に「正解は「…」」を含む
